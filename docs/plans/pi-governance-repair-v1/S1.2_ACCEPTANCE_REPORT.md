## AC 映射

### S1.2-AC01 — 大于 4 MiB 的同尺寸尾部修改被检测：PASS

场景 A 的 `large-input.js` 为 `6,213,092` bytes。worker 修改发生在 4 MiB
前缀之后：

- before full SHA：`e8f349eabd48486bdb2bf9dc1a00c89d58297270c54b745838879e2859194419`
- after full SHA：`d84a60388194a82d671d3650471f3e8e0c7d7b1bb2274204bfb0afd80e5610eb`
- before/after 大小完全相同。
- before/after 前 4 MiB SHA 完全相同：
  `98539f74bbb251350d497332d9c085f769141cf61a2c50f06971d676dad36e47`
- journal 完整读取 before+after 共 `12,426,184` bytes，ChangeSet finalizer
  再读取 touched path `6,213,092` bytes；最终为 `ATTRIBUTED`，worker delta
  hash 为 `31524d09fa92e309537287b594f7efe13955ef0de9160567cba09596a5261219`。

因此旧的“相同大小+相同前 4 MiB”身份会漏检，而 v2 完整流式 SHA 正确检测。

### S1.2-AC02 — 已脏文件的本轮变更可准确归因：PASS

场景 B 在 delegation 前已有 `201` 个 tracked dirty paths：`probe.txt` 从提交态
`BASELINE` 预先变为 `PREDIRTY`，另有 200 个 unrelated dirty files。worker
只把 `probe.txt` 改为 `WORKER01`。

- journal before identity 绑定 `PREDIRTY` SHA
  `b56937ada1689fa02492dd257e4a8ca62a677c946ea4ca8888cd344a063570da`。
- journal after identity 绑定 `WORKER01` SHA
  `aaac6294481881b3dca892bf745e6659083f384b6fff6e1b01b4f8fbdf658470`。
- ChangeSet 仅归因 `probe.txt`，200 个 unrelated paths 不进入 worker delta。
- B 与 clean-control C 产生相同 worker delta hash：
  `6282b55f84ae0dd11ea61632ebfb64f9f17ce6d4421b4ded7713be529b904ddf`。

### S1.2-AC03 — 无关 artifact/report 漂移不令已审查 source delta STALE：PASS

文件 SHA 在变更前后均为
`75391a4f36502fe682da2a1f39ed240a46060326d61c4cb660abf021fa712306`。

扩展验证 B：FINAL/PASS 后修改已知的 unrelated baseline path
`unrelated/000.txt`，fresh-process review 仍 PASS，review SHA 前后均为
`ae01ebf4e98f73da8f6389b227e137ae4283078da38f2d23f10060ed8f6c39f4`。

### S1.2-AC05 — 小修改读取量与 touched paths 成正比：PASS

B（200 个 unrelated dirty files）与 C（无 unrelated dirty files）执行相同的
`PREDIRTY → WORKER01` 单路径修改：

| 指标 | B | C |
| --- | ---: | ---: |
| journal paths attempted/completed | 2/2 | 2/2 |
| journal content bytes read | 18 | 18 |
| finalizer paths attempted/completed | 1/1 | 1/1 |
| finalizer content bytes read | 9 | 9 |
| worker delta paths | 1 | 1 |
| relevance projection entries | 7 | 7 |

因此 full-content identity 成本只随 touched/relevant paths 增长，不随 200 个已知
unrelated dirty files 增长。Git status 仍需枚举工作区元数据；本 AC 的结论限定为
此前造成主要成本和 4 MiB 漏检风险的文件内容读取，不虚构 status 元数据为常数。
