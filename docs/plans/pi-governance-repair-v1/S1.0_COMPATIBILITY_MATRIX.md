## v1→v2 read / recover / gate-eligible 矩阵

`gate-eligible` 表示“可进入后续正式判定的候选”，不等于测试 parse PASS，更不等于
当前正式 gate 已 PASS。任何 current-state、身份、完整性、freshness 或 Sol ownership
条件缺失都必须 fail-closed。

| v1 类别 | Read | Recover | Gate-eligible | v2 兼容要求 |
| --- | --- | --- | --- | --- |
| 完整 delegation v1 | 只读展示 | 无通用恢复 API | 否：ledger 不是直接 gate evidence | v2 保留只读；不得把 v1 optional files 推断成 committed generation |
| running/partial delegation v1 | 当前 reader 可返回 manifest+before | 否 | 否 | 显式标为 incomplete/legacy；不自动完成 |
| missing/foreign/corrupt delegation core | manifest/before 故障拒绝；after/summary 故障当前被降为 `null` | 否 | 否 | v2 必须识别完整 generation/commit marker 后才进入 review |
| 完整 run v1 | 是 | 无通用恢复 API | 条件性：必须 terminal、身份一致、validation binding/current state/recipe 条件全部满足 | v2 继续只读 v1；不能由 `schema_version` 单独授权 |
| partial/unknown run v1 | 否 | 否 | 否 | 明确 legacy/corrupt，不补写历史 manifest |
| foreign-ID run v1 | **当前 reader 接受（缺陷）** | 否 | 否 | v2 reader 必须校验 directory ID == persisted ID |
| 完整 gate v1 三件套 | 是 | 可严格重建 requested/prerequisite/manual facts | 条件性：身份一致三件套只是候选，仍需当前 gate/freshness/validation 判定 | v2 保留严格 fail-closed read；不得把 fixture parse 结果宣称为正式 authority |
| 缺失/损坏/冲突 gate v1 | 否 | 否 | 否 | v2 不补全、不合并冲突 artifact |
| 完整 matching receipt wtr1 | strict parse | `completed` | 否：固定免责声明为 presentation only | v2 保留只读恢复或显式 legacy renderer，绝不作为验收证据 |
| started-only receipt wtr1 | strict parse started | `incomplete` | 否 | 不重放原工具、不自动 finalize |
| corrupt/conflicting receipt wtr1 | 单 phase 可分别 parse；组合严格失败 | `corrupt`/`conflict` | 否 | fail-closed，保留诊断，不覆盖历史 bytes |
| 完整 validation binding v1 | strict parse | 仅 exact current state 可 `reusable` | 条件性：successful+complete+Sol owner+所有 identity facts exact | v2 未迁移时只读比较；unknown version 是 legacy，不能乐观采用 |
| partial/foreign/unknown validation v1 | partial/unknown 拒绝；foreign target 可 parse | fixed refusal reasons | 否 | 保留 deterministic refusal，不把旧 evidence 升级成 current authority |

## 必须保持的合同与已知缺陷

必须保持：receipt 两阶段严格 identity/cross-phase 检查和固定恢复码；gate 三件套的
严格 identity reconstruction；validation evidence 的固定 refusal reason 顺序；所有
读取有界、只读、失败关闭；11 个 public tool 的注册顺序、参数 schema、静态 metadata
和可观察结果类别。

当前缺陷（只 characterization，绝不是目标合同）：

1. `readDelegationLedger` 不验证 `schema_version`/完整字段；missing 或 unknown
   manifest schema 仍可读取，missing/corrupt optional after/worker-summary 被降为 null。
2. `readManifest` 只验证 `schema_version`，未校验 directory ID 与 persisted
   `run_id` 一致；foreign-ID fixture 当前可读取。
3. delegation content identity 对大文件只包含前 `MAX_DIGEST_BYTES`（4 MiB）前缀
   与总大小；同尺寸尾部变化可得到相同 v1 digest。characterization test 固定这一
   缺陷，S1.2 必须用完整流式 hash 修正。

## Verification contract

声明 recipe exact commands：`npm run typecheck` 与 `npm test`。focused 尝试只能
使用 `npm test -- --test-name-pattern="governance v1"`；若 runner 不真正聚焦或环境
拒绝 tsx IPC，则按冻结规格回退完整 `npm test`，不得另造 VERIFY 命令。

在新增资产尚未进入 index（仍为 untracked）时，`git diff --check` 不会读取
它们，exit 0 不能作为空白合规证据。pre-stage 内容检查必须实际读取目标
regular files，并对 `rg` 的“无匹配”与执行错误做区分：

```bash
if rg -n '[[:blank:]]+$' tests/governance-v1-characterization.test.ts tests/fixtures/governance-v1 docs/plans/pi-governance-repair-v1/S1.0_COMPATIBILITY_MATRIX.md; then
  echo 'trailing blank whitespace found' >&2
  exit 1
else
  status=$?
  if [ "$status" -eq 1 ]; then
    echo 'no trailing blank whitespace'
  else
    exit "$status"
  fi
fi
```

同一目标集还必须用下列只读检查递归枚举 regular files，拒绝 CR byte
或缺少最终 LF；成功输出中的数量是实际读取的文件数：

```bash
node --input-type=module -e '
import { readFileSync, readdirSync, statSync } from "node:fs";
const files = [];
const walk = (path) => {
  const stat = statSync(path);
  if (stat.isDirectory()) {
    for (const name of readdirSync(path)) walk(`${path}/${name}`);
  } else if (stat.isFile()) {
    files.push(path);
  }
};
for (const path of process.argv.slice(1)) walk(path);
const failures = [];
for (const path of files.sort()) {
  const bytes = readFileSync(path);
  if (bytes.includes(13)) failures.push(`${path}: contains CR byte`);
  if (bytes.length === 0 || bytes[bytes.length - 1] !== 10) {
    failures.push(`${path}: missing final LF`);
  }
}
if (failures.length > 0) {
  console.error(failures.join("\n"));
  process.exit(1);
}
console.log(`checked ${files.length} regular files: no CR bytes; final LF present`);
' tests/governance-v1-characterization.test.ts tests/fixtures/governance-v1 docs/plans/pi-governance-repair-v1/S1.0_COMPATIBILITY_MATRIX.md
```

只有目标已被跟踪或进入 index 后，`git diff --check -- <paths>`（tracked
worktree diff）与 `git diff --cached --check -- <paths>`（index diff）才可作为补充
evidence；它们不取代上述直接内容检查，也不得为未跟踪文件产生 PASS。
